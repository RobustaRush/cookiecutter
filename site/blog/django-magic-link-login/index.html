How to add magic-link login to Django

The user types an email address, gets a one-time link, clicks it, and is signed in. There is no reset flow to build and no social providers to register.

django-mail-auth is one small dependency that ships three pieces: mailauth for the backend and the /accounts/login/ views, mailauth.contrib.admin to put the Django admin behind the same flow, and mailauth.contrib.user for an EmailUser model with no password field.

uv add django-mail-auth

Decide the user model first

This one is hard to walk back, because it lands in your first migration. Three routes: use mailauth.contrib.user and set AUTH_USER_MODEL = "mailauth_user.EmailUser"; write your own custom user with email as the USERNAME_FIELD; or stay on stock auth.User.

Stock auth.User is the one to avoid. Its email field has no unique=True. When two rows share an address, MailAuthBackend.authenticate() returns whichever it finds first and raises nothing. So anyone who can sign up twice with someone else's address can receive a link that logs them in as that user. If you must stay on stock auth.User, add a UniqueConstraint by migration and a validator on the admin form.

Settings

Edit INSTALLED_APPS in place here rather than appending. Django resolves admin templates and the admin login view in app order, so the overriding app has to load first — put mailauth.contrib.admin above django.contrib.admin. Get that backwards and the stock password login stays on /admin/ with no warning.

INSTALLED_APPS = [
    # ... existing entries kept ...
    "mailauth.contrib.admin",   # must precede django.contrib.admin
    "django.contrib.admin",
    "mailauth",
]

AUTHENTICATION_BACKENDS = [
    "mailauth.backends.MailAuthBackend",
    "django.contrib.auth.backends.ModelBackend",
]

LOGIN_URL = "mailauth:login"
LOGIN_REDIRECT_URL = "/"

Then path("accounts/", include("mailauth.urls")) — no namespace argument, the package declares app_name itself.

Templates and email

The package ships the email body and subject, and expects you to supply the HTML pages: registration/login.html, registration/login_requested.html, and registration/logged_out.html. It also needs a working email backend. With EMAIL_URL=consolemail:// the link prints to runserver output. With nothing configured, Django's SMTP default points at localhost:25, and the login form accepts the address and then nothing arrives.

Or hand it to your agent, which reads the wiring above from a maintained reference file and applies it to your repo:

/django-seedkit add passwordless magic-link login

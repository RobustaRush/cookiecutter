How to use Tailwind CSS in Django without Node

No package.json, no node_modules, no webpack. Tailwind ships a standalone binary, and django-tailwind-cli downloads it and drives it from a management command.

uv add django-tailwind-cli
# config/settings/base.py
INSTALLED_APPS = [
    # ...
    "django_tailwind_cli",
]

STATICFILES_DIRS = [BASE_DIR / "assets"]
TAILWIND_CLI_VERSION = "4.3.2"

Pin the CLI version, and not only in production. Tailwind 4 point releases can change what the build emits, and an unpinned CLI means CI builds different CSS than you did.

Create the directory before you boot. Django validates STATICFILES_DIRS at startup and raises if an entry isn't a real directory on disk — so a fresh clone fails on runserver with an error that says nothing about Tailwind. Run mkdir -p assets, and remember that an empty directory won't survive a git clone on its own.

The template tag

One tag handles both environments: in development it points at the live-rebuilt file, in production at the collected one. No {% if debug %} anywhere.

{% load tailwind_cli %}
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    {% tailwind_css %}
</head>
<body class="bg-gray-50 text-gray-900">
    {% block content %}{% endblock %}
</body>
</html>

Forgetting {% load tailwind_cli %} is the most common way to get an unstyled page — Django renders the missing tag as nothing rather than failing.

Development

python manage.py tailwind runserver

That runs the watcher and the dev server under one autoreloader, and passes every runserver flag straight through. The first run downloads the binary into .django_tailwind_cli/ and generates a source CSS file; both are gitignored for you.

One Tailwind 4 change worth knowing: templates are discovered through @source directives in that source CSS, not by scanning your project. Add a new templates directory and you add a matching @source line, or its classes get purged out of the build.

Or hand it to your agent, which reads the wiring above from a maintained reference file and applies it to your repo:

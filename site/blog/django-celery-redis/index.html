How to add Celery to Django with Redis

Django has no background-task system of its own. Celery gives you workers, retries, rate limits, and schedules — with Redis as the broker, that's one package and two files.

uv add 'celery[redis]'

Celery needs an app object that loads Django's settings. Put it beside your settings module and import it from the package __init__.py, so it exists before any task module is imported.

# config/celery.py
import os
from celery import Celery

os.environ.setdefault("DJANGO_SETTINGS_MODULE", "config.settings.production")

app = Celery("config")
app.config_from_object("django.conf:settings", namespace="CELERY")
app.autodiscover_tasks()
# config/__init__.py
from .celery import app as celery_app

__all__ = ("celery_app",)

Default that settings module to production, not local. A worker started without DJANGO_SETTINGS_MODULE in its environment should come up with production hardening; your dev shell names config.settings.local to override it.

Settings

The CELERY namespace means every setting below is read off Django's settings object. Give the broker and the result backend their own Redis database numbers, and keep a note of which number belongs to what — the cache, a channel layer, and a rate limiter all want one too.

REDIS_URL = env("REDIS_URL", default="redis://127.0.0.1:6379").rstrip("/")

CELERY_BROKER_URL = f"{REDIS_URL}/1"
CELERY_RESULT_BACKEND = f"{REDIS_URL}/2"
CELERY_BROKER_CONNECTION_RETRY_ON_STARTUP = True
CELERY_TASK_SOFT_TIME_LIMIT = 540
CELERY_TASK_TIME_LIMIT = 600

The .rstrip("/") matters when the URL comes from a managed Redis provider: a trailing slash builds redis://host:6379//1, which is a different database than you meant.

Set both time limits. Celery ships with none. A task that hangs on a socket read holds its worker slot forever, and enough of them stop the queue moving with no error anywhere, because nothing failed. The soft limit raises SoftTimeLimitExceeded inside the task so it can clean up. The hard limit kills the process if it doesn't.

Run it locally in a second terminal, with Redis already up:

DJANGO_SETTINGS_MODULE=config.settings.local uv run celery -A config worker -l info

Or hand it to your agent, which reads the wiring above from a maintained reference file and applies it to your repo:

/django-seedkit add Celery background tasks

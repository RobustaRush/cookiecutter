How to lock out brute-force logins in Django

Django counts no failed logins and rate-limits nothing. Whoever finds your login form can try passwords until they run out. django-axes records every attempt and locks the source out after a threshold.

uv add django-axes
# config/settings/base.py
INSTALLED_APPS += ["axes"]
MIDDLEWARE += ["axes.middleware.AxesMiddleware"]

AUTHENTICATION_BACKENDS = [
    "axes.backends.AxesBackend",
    "django.contrib.auth.backends.ModelBackend",
]

AXES_FAILURE_LIMIT = 5
AXES_COOLOFF_TIME = 1                                # hours
AXES_LOCKOUT_PARAMETERS = [["ip_address", "username"]]
AXES_RESET_ON_SUCCESS = True

Then manage.py migrate: axes ships its own models to record attempts. Append to INSTALLED_APPS and MIDDLEWARE rather than redeclaring them, so anything your production settings add survives. AxesMiddleware belongs last: it wraps every other middleware's authentication attempts.

AxesBackend must come first. Put it after ModelBackend and you turn lockout off: the first backend authenticates the request before axes ever sees it. Nothing raises, nothing logs, and the package still shows up in pip list. The only way to catch it is to fail six logins on purpose and watch the seventh succeed.

Lock on both, not either

Note the nested list in AXES_LOCKOUT_PARAMETERS. Nesting means and: lock the combination of this IP and this username. A flat ["ip_address", "username"] means or, meaning either one alone, and username-only lockout hands anyone a denial-of-service. They submit five bad passwords for your address, and you can't log in for an hour.

Behind a proxy

If Django sits behind Caddy, nginx, or a load balancer, REMOTE_ADDR is the proxy's address on every request — so all traffic looks like one client and the IP half of the lockout stops meaning anything. Install the extra and point axes at the forwarded header:

uv add 'django-axes[ipware]'
AXES_IPWARE_PROXY_COUNT = 1
AXES_IPWARE_META_PRECEDENCE_ORDER = ["HTTP_X_FORWARDED_FOR", "REMOTE_ADDR"]

Check it by failing a login from a known address and reading the axes_accessattempt table. If the IP recorded there is your proxy's, the header isn't reaching axes.
